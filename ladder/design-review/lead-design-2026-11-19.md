# Choosing Seldon Lead — design for Oren, 19 November 2026

**Proposal.** Choose at kickoff who manages implementation. In Orchestrator, Seldon coordinates several workers against an approved plan. In Lead, Seldon and the owner grow the dream, then one builder session takes each milestone from brief to integrated candidate. In both shapes the owner decides what counts as the dream and Seldon independently checks the result.

## One codebase

Expose the choice in provider chat when starting a run. For the trial, `SELDON_MODE=lead` selects Lead when kickoff has no explicit choice. An explicit chat selection wins. Unset means Orchestrator, an unknown value produces a setup correction, and a pre-mode saved kickoff means Orchestrator. Persist the selection before ALIGN. Reopen always reads kickoff. Choosing a mode and estimating dream size are separate decisions.

Share R18 grow/A, typed decisions and user origin, controller lease, provider recording, Git, observations, judgment, memory source and C decision capture. Branch once after A by persisted mode. Lead's own milestone transitions issue one builder brief. Keep mode-specific subject and eligibility logic behind the owning transition. Prefer extracting the small Git publication or observation operation both paths need to parameterizing the unit scheduler. The Lead eligibility decision consumes milestone proof directly.

The development precedent is concrete. The ladder AGENDA ranks outcomes and reserves charter changes for Oren. HANDOVER carries faults and next actions across sessions. The growChat brief/report follows a displayed question through a real consumer and reconnect. The prompts2 report leaves product scoring pending after a prompt change. Lead should give a new builder exactly those kinds of facts. The store supplies their provenance.

## Test order and decision rule

1. Keep the owner's current micro-first gate. Ratification permits preparing the trial. A bigger dream waits for the micro bar. Check the integrated candidate with the normal gate under default settings and cold imports. Use offline strict-schema journeys for mode routing, recovery and authority. A recording or scripted provider can prove the controller's behavior. Live behavior needs a real provider run.
2. Run **hello × 5, Foundation × 5, ShelfLife × 5, Quiet Bench × 5** in Lead on a named candidate under the ladder's Terra test policy. Pin the candidate, rig, feature settings, provider and oracle per slot. Keep the owner's requested stages. Unique slots, stall alarm and a ten-minute check for each live run. Score the exact delivered folder with the sealed oracle and inspect source, commands, guide and actual UI where applicable. Use the existing matched plain micro controls where comparable.
3. Pass requires **20/20 reach C**, five clean for each dream, **zero step failures, zero stall-alarm loops, zero bookkeeping refusals and zero Seldon-fault questions**. Count recovered failures. Report ordinary A/B/check-in/C touches separately. Label proxy/scripted C. On a fault, keep the failed slot and its receipts, fix the canonical cause, rerun the affected dream's five on the repaired candidate and identify the basis for retaining unaffected results. If a shared change invalidates an earlier cohort, rerun it before declaring the bar met. A clean controller still needs oracle and hands-on product findings beside it.
4. Only later, after the micro gate and intervening ladder prerequisites, compare **Lead / Orchestrator / plain multi-session** on the same held-out medium dream. Use five matched triples and rotate arm order. Freeze a common brief, approved growth choices, exact constraints, start tree, milestone boundaries, provider/model/effort by role, tool access and sealed oracle. Give plain a competent native builder in each session with its own ordinary handoff, the same owner decisions and access to its previous product. Require a real context handoff in every arm and a later change that exercises an earlier promise. Keep private judging materials out of the builders' workspaces.
5. Blind the artifact labels for black-box scoring and hands-on review on all three arms. Report kept/lost owner promises by milestone and at the finish, source quality, usable guide, owner interventions, wall/human time, calls, recoveries and fresh tokens or billed cost (including visible native helpers). For plain, use delivery-ready plus the same independent final walkthrough as the common endpoint. Show Seldon's C status separately. Keep all starts and unknowns. Before opening results fix the material quality criteria and cost tolerance with Oren. Favor Lead for the medium use case only if it preserves those promises across sessions and its measured cost/quality tradeoff warrants it. Micro cleanliness alone cannot settle that choice.

## Risks that change the trial

| Risk | Decisive observation and response |
|---|---|
| A helper keeps writing after its parent returns or can reach Seldon's records. | Attempt a benign out-of-workspace write and an interrupted helper on each candidate provider configuration. Require denial and verified quiescence before independent proof or writer replacement. Use supported native containment. If the provider cannot enforce it, keep that capability unavailable and disclose why. |
| A confident judge sees inadequate evidence. | Use the Quiet Bench Stop case with one working and one broken product. Capture action, progress and partial-result state. Blind the evidence labels. If the evidence cannot distinguish the cases, repair observation before tuning the judge. Include clean controls. |
| Memory drifts or cumulative proof becomes expensive. | Reopen without the rendered baton and compare the next brief to the accepted decisions. Time the cumulative check set per milestone. Combine overlapping journeys only when each promised outcome is still observed on the new candidate. |
| Hidden helper costs or a single weak builder distort the comparison. | Record native capability, effective model, retries and visibility of child usage. Mark unknown totals and separate Terra micro results from any conclusion about strong builders. |
